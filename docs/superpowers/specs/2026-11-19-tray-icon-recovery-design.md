# 岛仔托盘图标登记恢复设计

日期：2026-11-19

## 背景与证据

岛仔主进程、托盘窗口和消息循环均存活，但主通知区与隐藏图标列表中都没有岛仔。Windows 对当前托盘 `hWnd + uID=1` 查询返回 `E_FAIL`。使用同一托盘窗口和同一图标资源，由正常外部进程调用 `Shell_NotifyIconW` 可以成功显示图标；岛仔自身响应 `TaskbarCreated` 后仍未恢复。

当前 `src/tray.rs` 在启动时调用一次 `add_icon`，虽然保存了布尔结果，但 `Tray::start_with_exit` 将结果丢弃。失败后没有错误细节，也没有定时重试；只有 `TaskbarCreated` 会再次尝试。因此一次失败会表现为持续缺失，且缺少进一步定位证据。

### 根因结论（2026-11-19 实测）

诊断补丁上线后读到 `icon_last_result=失败(阶段=Modify, 系统错误=5)`，`NIM_ADD` 与 `NIM_MODIFY` 均返回 **错误 5（拒绝访问）**，`cbSize` 正确（976）。逐项实测排除了图标资源、窗口样式、`uID`、`cbSize`、调用时序：

- 同一托盘窗口、同一 `uID=1`、同一时刻，由高完整性进程（0x3000）调用登记**成功**；
- 岛仔进程的令牌完整性实测为 **0x1000（中）**，而 Explorer 与桌面大多数用户程序为 **0x3000（高）**；
- Shell 在完整性级别不一致时拒绝跨级别托盘登记，因此返回拒绝访问。

进一步定位到启动路径：同一个 exe 复制到 `%TEMP%` 后从该目录启动，完整性为 0x3000，托盘图标**正常显示**（`Shell_NotifyIconGetRect` 返回 0x00000001，矩形落在通知区）；从 `D:\Codex\daozai\target\...\release` 启动则固定为中完整性。该目录带有 `CodexSandboxUsers` 沙箱 ACL（`D:\Codex` 起即设置了沙箱用户组权限），在此路径下启动的子进程会被放入沙箱作业并以中完整性运行，所以托盘登记被拒。

结论：**这是构建产物所在目录的沙箱属性导致的部署问题，不是托盘代码缺陷**。程序侧无法自行提权（自提权会引入 UAC 绕过风险，不符合项目安全边界），因此修复策略为：

1. 补齐登记诊断，错误码 5 时给出明确可执行提示（以管理员身份启动或换非沙箱存放位置）；
2. 增加非阻塞有界重试，覆盖真正的临时性失败（如 Explorer 重启、桌面尚未就绪）；
3. 交付时把 release 产物放到非沙箱目录后再由桌面快捷方式启动，实机确认图标落在通知区。

## 方案比较

1. **登记诊断与有界恢复（采用）**：保留现有原生托盘结构，补充失败原因、有限次间隔重试和回归测试。改动集中，能自动恢复临时失败，也能暴露持续失败原因。
2. **仅重启岛仔或 Explorer**：可能暂时恢复，但不能防止复发；重启 Explorer 还会干扰整个任务栏。
3. **引入第三方托盘库重写**：会同时影响菜单、单实例、退出清理和 Agent 消息接线，风险与本次问题不相称。

## 设计范围

只修改 `src/tray.rs` 及其托盘测试。保留以下既有行为：

- `uID=1`、`WM_APP+9` 回调和现有中文菜单；
- 托盘线程、Rust 主进程事件通道和 Agent 固定消息；
- `TaskbarCreated` 重建、退出时 `NIM_DELETE` 和图标资源释放；
- 现有单实例、自动启动和 Agent UI 代码。

不修改 Windows 通知区设置，不重启 Explorer，不引入新依赖，不改动其他未提交功能。

## 实现设计

### 登记结果与诊断

将托盘登记封装为可测试的小边界：真实实现仍调用 `Shell_NotifyIconW`，测试可注入失败结果。每次尝试记录：

- 当前是否已登记；
- 尝试次数；
- `NIM_ADD` 是否成功、是否执行了 `NIM_MODIFY` 回退；
- 最近一次失败的系统错误信息。

诊断信息不得包含请求正文、回答或其他 Agent 数据。现有 `WM_TRAY_DUMP` 输出同步补充登记状态与最后错误，便于实机取证。

### 有界重试

首次 `NIM_ADD` 和必要的 `NIM_MODIFY` 都失败时，在托盘线程设置独立重试定时器，不阻塞 `GetMessageW`、菜单或 Agent 消息处理。

- 采用短间隔递增重试，最多 5 次补充尝试；
- 成功后立即停止定时器并更新登记状态；
- 达到上限后停止自动重试，避免无限调用和重复图标；
- `TaskbarCreated` 到来时立即尝试，并重新开始同一套有界策略；
- 重试只针对未登记状态，已登记时不重复添加。

### 测试

遵循测试先行，先观察新测试在现有实现上失败：

1. `NIM_ADD` 失败且 `NIM_MODIFY` 失败时，返回带阶段的错误并安排重试，不得误报已登记。
2. `NIM_ADD` 失败后 `NIM_MODIFY` 成功时，视为登记成功，不安排无意义重试。
3. 持续失败达到上限后停止；成功后不再重试；`TaskbarCreated` 可以触发新的恢复序列。
4. 既有托盘消息、菜单顺序、图标资源和 Agent 固定消息测试保持通过。

### 实机验收

1. 运行托盘定向测试和相关 Rust 回归，执行 `git diff --check`。
2. 构建 `x86_64-pc-windows-msvc` release。
3. 重启到桌面“岛仔－当前测试版”指向的固定 release 程序。
4. 用 `Shell_NotifyIconGetRect` 确认 `hWnd + uID=1` 已登记，并目视检查主通知区或隐藏图标列表。
5. 右键托盘打开菜单，确认设置与退出入口可用。
6. 核对快捷方式目标、release SHA-256 和运行进程路径。若自动登记仍失败，使用扩展后的诊断 dump 继续定位，不宣称修复完成。
