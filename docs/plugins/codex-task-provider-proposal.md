# Codex 任务插件接口提案

关联：#138

## 使用场景

在 Windows 上让 Codex 执行后台任务时，可以在岛仔查看任务状态，收到任务完成或需要处理的提醒，并打开对应的 Codex 桌面会话。插件负责显示，岛仔宿主负责获取状态、处理通知和打开会话。

## 第一阶段：只读状态和跳转

建议增加专门的任务来源能力。以下字段和动作是供评审的接口草案，名称可以按 SDK 约定调整。

| 接口 | 建议行为 |
| --- | --- |
| 本机任务快照 | 用户启用后，由宿主提供任务名、状态、更新时间和宿主生成的不透明任务标识。状态包括执行中、等待审批、等待回复、已完成、失败和未知。只展示连接端能够确认的状态。 |
| 打开任务 | 用户主动点击后，插件将快照中的任务标识交给宿主。宿主验证标识仍然有效，并打开对应的 Codex 桌面会话。 |
| 状态展示 | 在已有的状态页和常驻位展示任务。完成或需要操作的提醒遵循岛仔已有的通知设置。任务数据源不可用时显示状态未知或未连接。 |

同一会话的状态更新沿用原标识。列表里有多个会话时，点击任意行始终使用该行关联的标识。任务消失或标识过期时，宿主提示任务已不可用。插件无需获得通用进程执行、任意文件读取或自定义协议跳转权限。

## 第二阶段：审批和快捷回复

审批与回复建议另行评审。只有连接端能够确认待处理请求归属，并支持向同一会话提交响应时，才显示相应按钮。由宿主展示操作摘要、接收用户选择，核验请求与会话的绑定关系并处理请求已过期或已回复的情况。已有桌面会话如果没有受支持的响应渠道，继续提供「打开会话」。

## 隐私与兼容

任务状态是可选功能，默认保持关闭。插件获得的只是展示所需字段。会话正文、命令输出、工作目录、账号凭据和原始记录都留在本机连接端。关闭权限后清空已展示的状态并停止更新。旧版宿主按现有 SDK 版本检查提示升级。

本地原型已经验证了任务提示、桌面会话列表跳转、独立详情，以及由岛仔发起的会话中审批与回复的请求绑定。原型使用的桌面端本机记录格式可能随 Codex 版本变化，建议由宿主适配并独立处理不可用状态，不将这部分格式作为插件 API。

## 验收建议

- 使用虚构任务验证执行中、完成、连接中断和未知状态，确认提醒只在状态变化时触发。
- 同时展示两个任务，确认各行只能跳转到自身对应的会话，过期任务提示不可用。
- 关掉授权后，状态卡和常驻徽标移除，插件无法继续获得任务快照。
- 使用合成请求验证审批和回复只能发送给匹配的会话，并拒绝已处理的请求。
