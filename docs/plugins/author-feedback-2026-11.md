# 插件作者实操反馈：独立设置页、本地安装与两处文档缺口

> 背景：给岛仔做定制版时写了一个 `status.page` 插件（节假日倒计时），从写清单到装上岛
> 完整走了一遍。以下是实际卡住的地方，按影响排序。全部基于 0.6.70。

## 1. 插件装好后没有自己的设置入口

`status.page` 插件装完，要改它的参数只能去「设置 → 页面管理 → 状态详情」里翻，和插件本身
没有直接关系；「已安装」列表里的「前往设置」跳到的是 `owner` 所属页（status 统一跳页面管理）。

文档里「可编辑独立模块 · 待宿主实现」一节（`docs/plugins/sdk-v1-design.md:37`）提到
`owner: "self"` + `module` 的形态，看起来正是为这种需求准备的，但 0.6.70 里没有实现。

**建议**：让插件清单可以声明自己的设置页入口，或者至少让「已安装」行的「前往设置」优先
跳到插件自己的设置区块，而不是先到所属大页里找。

## 2. 本地安装只吃 `plugin.json`，不吃 zip，且选错文件时提示误导

开发者工具的「安装本地插件…」只接受开发目录里的 `plugin.json`。我按常识先拖了一个打包好的
zip 进去，得到的提示是：

```
插件 / 文件过大
```

而实际上包只有 69 KB，全部上限（整包 832 KB、封面 256 KB、脚本 256 KB）都远未触及。
真正的判定在 `spike/local.rs:750`：拿到的路径不是 `plugin.json` 就直接失败，
但如果文件先被读进 `bounded()`，就会先撞上体积/编码检查，报出与原因无关的错。

**建议**：
- 支持直接导入集市同款 zip（本地调试和投稿复用同一个包，省一次打包/解包的认知负担）；
- 文件类型不对时先说「请选择 plugin.json」，不要报体积错误。

## 3. `statusLayout` 的组件名文档里没有完整列出

文档只给了示例（`state` / `progress` / `summary` / `metrics` / `alert`），我按直觉写了
`items` 和 `note`，宿主报：

```
unknown variant `items`, expected one of `state`, `summary`, `progress`, `metrics`,
`alert`, `updated_at`, `actions`, `fields`, `list`, `chart`, `text`, `badge`,
`counter`, `clock`, `countdown`, `canvas`
```

**建议**：把这 16 个组件名和各自可用字段补进 `sdk-v1-design.md`，现在只能靠报错反推。

## 4. `countdown` 不能只显示天数

倒计时只有 `d天 HH:mm` 和 `HH:mm:ss` 两种格式，做「距元旦还有 35 天」只能显示成
`35天 05:03`，时分是噪音。

**建议**：加一个只显示天数（或天+小时）的格式，例如 `d天` / `d天 H小时`。

## 5. `refresh` 返回里空值不能写 `null`

`{countdown: null}` 会被判 `invalid type: null, expected a sequence`。要么整字段不出现，
要么给空数组——但空数组是否合法、各字段的最小条数限制，文档没有统一说明。

**建议**：在返回结构那节写清「可省略」与「必须 N 条以上」的规则，省得逐个试错。

## 6. 「插件」应拆成「插件市场」和「插件管理」两页

现在设置侧栏只有一项「插件」，点进去是集市和已安装的混合体；「安装本地插件…」和「开发者工具」
藏在集市页右上角的弹窗里，新用户很难找到——我是照着引导文档才摸到的。

**建议**：
- 侧栏把「插件」改名为**「插件市场」**，只负责发现、下载、安装；
- 新增**「插件管理」**页，专门管已装的：启停、排序、卸载、更新、查看详情；
- 「开发者工具」独立成一项，或放在插件管理页底部，不要再塞进集市。

日常高频的是「管已装的」，不是「逛集市」，两者混在一起会互相稀释。

## 7. 已安装列表要显示作者，并支持在线更新

现在「已安装」每行只有名称、前往设置的路径、开关和「···」菜单，看不到作者，也不知道有没有新版本。
装过本地改动版之后，尤其分不清自己手里是不是最新的。

**建议**：
- 每行显示 `作者 · 版本`，跟随清单里的 `author` / `version`；
- 来源是集市的插件，检测到新版本时显示「有新版本」标记和「更新」按钮，直接拉作者发布的最新版；
- 本地目录安装的，显示「本地」标记，并提供「重新读取目录」，省得每次都要重新走一遍安装；
- 更新时保留插件设置与 `storage` 数据（文档里对集市更新有这条承诺，本地来源也应一致）。

## 小结

插件系统的骨架已经够用：清单、能力表、状态页布局、日历标注、定时刷新都能跑通，
上面几条主要是**可发现性和人机回路**的问题——装不上时不知道原因、能配什么只能靠报错猜、
装完找不到自己的设置。修这几处对作者体验的提升，比再加能力更直接。
