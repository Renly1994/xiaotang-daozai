## 1. 用户原始诉求（逐字保留）

> 我想开发一个应用程序，在 windows macOS 以及安卓上面都能用这个应用程序安装后会有一个主控制面板里面包含很多功能，比如说支持灵动岛，就是该项目原有的那些功能，还支持拖拽文件或者文件夹到灵动岛里面就能同步到其他端，比如我在 Mac 上拖拽文件或者文件夹在其他端登录了这个应用程序就能搜到对应的文件或者文件夹，一个大的前提是它是端到端的，没有服务器来支持你先规划一份详细的产品设计以及架构图，然后我们在一步步确认设计方案

拆解为四条硬约束：

| # | 约束 | 含义 |
|---|---|---|
| C1 | 三端可用 | Windows / macOS / Android 安装即用，同一套功能 |
| C2 | 主控制面板 + 灵动岛 | 保留现有岛体功能（时钟、待办、悬浮岛、安卓小组件），新增功能进面板 |
| C3 | 拖入即同步、跨端可搜 | 桌面拖文件/文件夹进岛 → 其他端能搜索到并取回内容 |
| C4 | 端到端、无服务器 | 项目不运营任何后端；数据只在用户自己的设备之间流动，中转方不可读 |

### 2.3 原 Rust 版的「置物架」——为什么不能直接满足 C3

原版有置物架页（`src/pages.rs:626`）和 OLE 拖放接收（`src/native.rs:332`，Windows 专属），但其数据模型是**只存本机绝对路径、不复制文件正文**（`src/model.rs:834` 注释："the shelf remembers where your files live"；`shelf.txt` 每行一个路径）。

结论：路径在另一台设备上无意义。**跨端同步必须复制内容进应用管理的存储区**，这是与原版置物架的本质区别，也是新功能的立足点。原版拖放的交互经验（拖入感应区才扩大接收区域、去重/失败计数提示，`src/app.rs:3470 on_drop`）值得复刻。

### 2.4 「端到端 + 无服务器」的技术边界（必须先说清）

无服务器 ≠ 无任何网络设施。两台设备要找到彼此并传数据，只有三类路：

| 路 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. 局域网直连 | mDNS 发现 + TCP 直传 | 完全无第三方、速度最快、真·零服务器 | 仅限同一 Wi-Fi/网段；安卓后台受限 |
| B. 公共中继（盲转发） | 借用公开基础设施（如公共 MQTT broker / WebRTC 信令）转发**密文** | 跨网可用（4G ↔ 家庭宽带） | 依赖第三方在线服务；中继方只见密文不见内容；离线消息能力取决于所选服务 |
| C. 用户自有通道 | 用户自己的网盘/WebDAV/Syncthing 目录当信箱 | 无项目服务器、跨网、天然离线队列 | 要求用户额外配置一个账号/服务，违背「安装即用」直觉 |

**推荐：A 为主干（MVP），B 为第二阶段可选增强，C 不做。** 理由：C4 的最强解读是「连第三方都不依赖」，A 完全满足；B 作为显式开关的增强项，密文经过公共中继不破坏端到端语义（中继无密钥）。此决策列入 §7 待确认。

## 3. 症状 / 复现（以现状验证缺口）

以当前 v0.1.0 安装包（macOS DMG / Windows zip / Android APK）复现：

1. **拖放无响应**：从 Finder/资源管理器拖任意文件到悬浮岛上 → 无任何反应（岛体未注册拖放目标；穿透态下鼠标事件甚至不进窗口）。
2. **跨端不可见**：Mac 与 Android 装同一应用、同一 Wi-Fi → 两端各自只有本机待办，没有任何设备列表/文件列表/搜索入口。
3. **无配对入口**：设置/右键菜单只有「关于」「退出」（`desktop_shell.dart:104-126`），无设备管理。
4. **面板装不下**：即使加了文件列表页，419×140 的面板一屏只能显示约 4 行，且搜索框无处安放。

预期行为见 §4 各需求的验收标准。

## 4. 功能需求（EARS 格式）

### R1 设备身份与配对（信任根）

- R1.1 当应用首次启动时，系统应生成本机设备身份密钥对（Ed25519）与设备名（默认「用户名 的 Mac/PC/手机」，可改），私钥存入平台安全存储（macOS Keychain / Windows DPAPI / Android Keystore）。
- R1.2 当用户在设备 A 上发起配对时，系统应显示配对码（二维码 + 6 位数字短码二选一）。
- R1.3 当设备 B 输入/扫描配对码且两设备可达时，系统应完成密钥交换（X25519 ECDH → 会话密钥），并在**两端同时**显示对方设备名与验证码指纹，双方确认后才建立信任。
- R1.4 若配对码错误或超时（120 秒），则系统应拒绝配对并给出可见错误，不留半配对状态。
- R1.5 当用户移除某已配对设备时，系统应删除其信任记录与会话密钥，此后拒收该设备的一切消息。
- R1.6 系统应仅在已配对设备之间传输数据；未配对设备的连接请求一律拒绝。

### R2 设备发现与连接

- R2.1 当应用在前台且同步功能开启时，系统应通过 mDNS（服务名 `_daozai._tcp`）广播本机并发现同网段已配对设备。
- R2.2 当发现已配对设备上线时，系统应在设备列表显示「在线」，并自动建立加密连接（Noise 风格握手，前向保密）。
- R2.3 当设备离线时，系统应显示「离线 · 最后在线时间」，其已同步的文件索引仍可搜索（内容取回需等上线或已有本地副本）。
- R2.4 若 mDNS 被路由器/防火墙拦截，则系统应提供手动输入 IP:端口 的连接兜底，并给出可见提示。
- R2.5 当同步功能被用户关闭时，系统应停止广播、断开全部连接，不再收发任何数据。

### R3 拖入收纳（桌面端）

- R3.1 当用户从系统文件管理器拖文件/文件夹进入岛体感应区时，系统应高亮岛体为「投放态」（视觉反馈），松手即收纳。
- R3.2 当收纳发生时，系统应将文件内容**复制**进应用存储区（不动原件），计算 SHA-256，建立索引条目：文件名、相对路径（文件夹保留结构）、大小、修改时间、来源设备、收纳时间。
- R3.3 当拖入的是文件夹时，系统应递归收纳全部子文件，保留目录结构，跳过符号链接与不可读文件并计数提示。
- R3.4 当同一内容（SHA-256 相同）再次拖入时，系统应去重：不重复占用空间，提示「已在置物架」。
- R3.5 当收纳完成时，系统应显示结果摘要（成功 N / 重复 N / 失败 N，对齐原版 `on_drop` 体验），失败项列出原因。
- R3.6 若单文件超过上限（默认 512 MB，可在设置调整）或磁盘剩余空间不足，则系统应拒绝收纳该文件并说明原因，不影响同批其他文件。
- R3.7 当岛体处于收起态时，系统也应接收拖放（拖入感应区自动展开为投放态，无需先悬停展开）。
- R3.8 安卓端无系统级拖放，系统应提供「添加文件/文件夹」按钮走系统文件选择器（SAF），效果等同 R3.2–R3.6。

### R4 跨端同步

- R4.1 当新文件收纳完成且存在在线已配对设备时，系统应先推送索引条目（元数据，KB 级），再按需传输内容。
- R4.2 当远端设备收到索引条目时，该文件应立即出现在远端的文件列表与搜索结果中，标注「在 <设备名> 上 · 未下载」。
- R4.3 当用户在远端点击未下载的文件时，系统应从源设备拉取内容（分块传输、断点续传、SHA-256 校验），完成后标注「本地副本」，并将明文文件导出到应用目录下的 `download/`（D5：Windows `<安装目录>\download\`，不可写时回落 `%LOCALAPPDATA%\DynamicIsland\download\`；macOS `~/Library/Application Support/DynamicIsland/download/`；Android 应用外部私有目录 `files/download/`），保留文件夹相对路径结构。
- R4.3a 当用户在设备页「下载位置」手动指定目录时（D5 补充，T1 即支持），系统应通过系统目录选择器（Win IFileOpenDialog / mac NSOpenPanel+security-scoped bookmark / Android SAF TREE+持久化 URI 权限）选定并校验可写，此后新导出去自定义目录；切换不搬家旧文件；目录失效时红条提示并回落默认，不静默丢文件；提供「恢复默认」。
- R4.4 当源设备离线时，系统应明确提示「文件在 <设备名> 上，该设备当前离线」，不提供假下载。
- R4.5 当用户在任一设备删除置物架条目时，系统应同步删除所有设备上的该条目、加密副本与 download/ 导出文件（回收站保留 7 天可恢复，超期物理删除）；**永不触碰源文件原件**。
- R4.6 当传输中断（断网/休眠/杀进程）时，系统应在恢复后自动续传，不产生半个文件冒充完整文件（临时文件 + 校验通过后原子改名）。
- R4.7 系统应对同一文件的多设备并发修改采用「最后写入胜出 + 冲突副本保留」策略，不静默丢数据。
- R4.8 当安卓应用退到后台时，系统应尽力保持连接（前台服务 + 通知栏常驻开关，用户可关）；被系统杀死后，下次打开应用应自动补同步增量。

### R5 搜索与文件面板（主控制面板）

- R5.1 系统应在岛体展开面板新增「文件」页（与待办并列，底部圆点切页），含搜索框 + 文件列表。
- R5.2 当用户输入关键词时，系统应按文件名/路径子串匹配（不区分大小写，中文原样匹配），实时过滤，结果标注所在设备与下载状态。
- R5.3 当用户点击本地已有副本的文件时，桌面端应提供「打开」「在文件夹中显示」；安卓端提供「打开/分享」（系统 Intent）。
- R5.4 当文件列表超过一屏时，系统应支持滚动；面板高度不足以舒适浏览时，提供「放大面板」进入大窗模式（复用 dialog_room 扩窗机制，扩展为可停留的文件管理视图）。
- R5.5 系统应提供独立的「设备」页：已配对设备列表（在线状态/最后在线时间/存储占用）、配对入口、移除设备。
- R5.6 当置物架为空时，系统应显示引导空状态（「拖文件到岛体，或点 + 添加」），不是空白。

### R6 端到端加密（安全需求）

- R6.1 系统应对所有设备间流量加密：握手 X25519 ECDH + 双向身份签名验证（防中间人），会话 AEAD（XChaCha20-Poly1305 或 AES-256-GCM），每会话独立密钥、前向保密。
- R6.2 系统应对落盘的收纳文件加密存储（AES-256-GCM，密钥由设备主密钥派生，主密钥在平台安全存储）；索引数据库同样加密或仅存于应用私有目录。
- R6.3 若启用第二阶段公共中继（§7 D2），则系统应保证中继只见密文与路由所需的设备公钥指纹，文件名/内容/搜索词一律不出现在中继可见字段。
- R6.4 系统应不在日志/诊断输出中记录文件内容、文件名全文、密钥材料。
- R6.5 当配对指纹两端不一致时，系统应中止连接并警告（可能遭中间人）。

### R7 基本体验闭环（HANDOFF 最高原则）

- R7.1 系统应为每个异步操作提供可见状态：配对中/传输进度/失败原因，禁止静默失败（沿用 reminderNotice 教训）。
- R7.2 系统应提供同步总开关与「仅 Wi-Fi 同步」开关（安卓防流量偷跑）。
- R7.3 当用户退出应用时，系统应干净断开连接、停止广播，不留幽灵端口/进程。
- R7.4 系统应保持现有功能零回归：时钟、待办、提醒、小组件、岛体手感全部不变，36 个既有测试必须继续通过。

## 6. 里程碑划分（D4=B：按端到端薄片切分，design.md §6 展开）

切分原则：每个里程碑都打通「拖入→同步→远端可搜可取」全链路的一个子集，交付即可用，不交付半成品层。

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| T1 双机直连薄片 | 身份+短码配对（手动 IP）+加密通道+单文件收纳+索引同步+按需拉取+download/ 导出与自定义目录（D5）+面板文件页搜索；vault/去重/上限/失败提示随片落地 | Mac↔Win 同 Wi-Fi 手动配对：拖入单文件→对端搜到→拉取打开，download/ 可见明文；回环集成测试过 |
| T2 三端完整薄片 | mDNS 自动发现+二维码配对；文件夹递归；安卓 SAF+文件/设备页；断点续传+离线判定；删除同步（无回收站） | 三端真机：Mac 拖文件夹→Android 自动发现→搜到→拉取；断网续传；删除全端生效 |
| T3 体验加固 | 回收站 7 天+冲突副本+大窗模式+存储管理+安卓前台服务+启动对账 | R4.5–R4.8、R5.4 全验收 |
| T4 跨网增强（可选，待 D2 决策） | 公共中继盲转发或打洞直连（实现既有端口） | 4G↔家庭宽带可搜可取；中继抓包只见密文 |

**MVP = T1 + T2**（D1：仅局域网）。每片收尾门禁：analyze 零警告 + 全部测试过 + CI 构建绿（T1 桌面两端，T2 起三端）+ 真机验收清单过。

## 8. 验收标准汇总（回归测试锚点）

以下每条都将在 tasks.md 对应至少一个自动化测试或真机验收步骤：

1. 拖入文件 → 原件不动、副本入库、SHA-256 正确、列表可见（R3.2）。
2. 拖入文件夹 → 结构保留、符号链接跳过、计数提示正确（R3.3）。
3. 重复拖入同内容 → 去重提示、存储不翻倍（R3.4）。
4. 超限/磁盘不足 → 拒绝且原因可见、同批其他文件不受影响（R3.6）。
5. 收起态直接拖入 → 自动展开投放态并收纳（R3.7）。
6. 配对码错误/超时 → 拒绝且无半配对残留（R1.4）。
7. 未配对设备连接 → 一律拒绝（R1.6）。
8. 两端指纹不一致 → 中止并警告（R6.5）。
9. Mac 收纳 → Android 搜索命中（元数据同步）→ 拉取后 SHA-256 一致，明文出现在 download/ 对应相对路径（R4.1–R4.3、D5）。
10. 传输中断恢复 → 续传成功、无半文件（R4.6）。
11. 删除条目 → 全端同步删（含 download/ 导出）、原件仍在、回收站 7 天可恢复（R4.5）。
12. 关闭同步开关 → 停止广播与连接（R2.5）。
13. 搜索：大小写不敏感、中文子串、设备归属标注正确（R5.2）。
14. 既有 36 测试零回归（R7.4）。
15. download/ 文件被手动删除 → 「打开」时从 vault 重新导出；Windows 安装目录不可写 → 回落路径且设备页明示（D5）。
16. 自定义目录：选定后新拉取落地新目录、旧文件不搬家；目录被移走/权限撤销 → 红条提示+回落默认完成导出；「恢复默认」生效（R4.3a）。
